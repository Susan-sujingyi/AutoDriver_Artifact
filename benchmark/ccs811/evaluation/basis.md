# CCS811 v2 评分依据与模型范围

仅宿主审计，不进入用户输入。原始设备依据为 artifact 内 ams DS000459 v1-06（2019-02-07）；具体哈希、原断言位置和旧新映射在 `benchmark/basis_v2/ccs811.json`。目标依据为实际 AirQuality HIL、air_quality capsule、I²C HIL 和应用后的 component。原参考已复跑原 v1：58/58；这个正控制不代替来源审查。

| 检查族 | 依据、处置和合法实现差异 |
| --- | --- |
| CCS-ABI | 实际 component 分配8字节，注册总线/Alarm，调用一次 startup；不引用 BUFFER_SIZE。保留实际构造与 trait 编译约束，不强制公开常量、startup 的精确返回类型或重启政策。 |
| CCS-CONFIG | 保留当前任务 mode1、已安装 application 2.0.0、nWAKE拉低/nRESET释放、0x5a 等配置选择。这是已有软件任务的部署前提，尚未在实物上核验。手册 p11、19 定义每秒输出与 mode字段；p11 明确 nWAKE 接地可行。无中断引脚不等于禁止无害的中断标志配置，不将所有非 mode 位强制成参考字节。 |
| CCS-NUMERIC | p12 健康固件的 eCO₂/TVOC 范围；p20 两个无符号大端字及 ppm/ppb，实际 HIL 使用相同单位。独立 oracle 只解码字节，不调用固件算法或方法 IR。0ppb、32768ppb 等端点有效。超出健康范围的输入作为异常固件诊断；不能从“固件通常输出此范围”直接推出驱动必须执行某种拒绝/钳位算法。 |
| CCS-DATA | p18 DATA_READY 在 ALG_RESULT_DATA 读取后清除；p20 允许2/4/5/8字节读取。清标志不删除已完成的读数。原模型只接受每通道严格新 generation，并清除错误后的所有历史，过度限制缓存。v2 保留已完成的采样证据，核对成功回调与实际读取的通道值，不强制每次都启动或等待新周期。冷启动最早可接受请求也测试，不能依赖评测者预先等足一周期来掩盖未就绪值问题。 |
| CCS-CALLBACK | AirQuality HIL 明确请求成功时对应数据回调，实际消费者按通道结束等待。允许排队/拒绝并发，不能产生重复、错误通道或未请求回调。HIL 的可能 BUSY/NOSUPPORT 说明不等于每种状态只能返回唯一错误码。当前 air_quality 消费者未在回调内部启动下一请求，不照搬 APDS 的同步重入要求。 |
| CCS-TIMING | p7 Figure7 将 APP_START 后1ms、普通reset后2ms 列在 Max 栏（普通reset的 Typ 为1ms）；上电 tSTART 的 Typ 为18ms、Max 为20ms。p8 Figure8 分别标示对应等待。首次新固件下载后的reset另有最多70ms注释。模型采用普通已安装固件场景，驱动创建与器件上电分开。尚未ready时的命令得到模拟NACK，允许重试，而不是直接断言某固定等待必须存在。4秒、50000事件和进程限额是监督策略；未完成单列。 |
| CCS-PROTOCOL | p18、20、26、27：邮箱长度、command-only APP_START、reset魔术序列、寄存器指针读法。保留有明文依据的非法传输检查。健康固定器件不强制HW_ID探测。固件缺失、可选环境/基线/下载命令及未建模读写单独诊断或 model_unsupported，不能以模拟器不支持当候选bug。 |
| CCS-FAULT | p18 的 ERROR清除需要读单独ERROR_ID，不是嵌入结果字段；v2模型仍保留这一硬件事实。但未发现“所有错误必须按参考路径立即清除、每次输送一个Err、限时重启”的接口要求。p24错误包含非法寄存器访问及加热器故障，单个ERROR位不能被泛化成所有缓存值都失效。故障、范围异常、重启、错误ID处理单列观察，不将其执行成功算进核心正确率。 |

本题验证数字估计值的传输和调用可用性。p12 的早期48小时变化、初次60分钟使用条件与20分钟run-in关乎化学稳定性/精度；合成邮箱不能验证这些物理属性，也不能因参考在几毫秒内初始化就声称其完成了调理。

原文件修补过的源头文件保持原有准入身份：选中的 C 和修复重复声明后的头文件是本题原始源输入，历史重复头文件与修复patch只留宿主来源记录。目标接线只调整泛型、8字节资源与客户端注册，不包含邮箱协议或数值算法。用户配置不附 APP_START 字节、ERROR_ID攻略或就绪策略。

S/D/SD 共用配置与目标工程。手册依据只在 D/SD 明确可得；S 提供原源码的实际实现，不能把旧source_conflicts作为额外资料。厂商资料中存在信息而某种条件没提供，与评分要求缺少依据，是不同问题。

v2 为29核心、21诊断、3模型自检；软件验收及冻结状态见总报告。核心包括22个数值条件、2个最早可接受请求、2个并发、2个稳定变化和1个跨通道采样。新旧分母按具体映射公开；旧故障/错误码/重入政策不偷偷保留为数值测试的隐藏前提。无真机、真实模型或方法成绩。

稳定输入进度监督进一步明确为 8000000 µs，与单请求完成窗口分开。绝对截止时间传入每次采样，轮询与回调后观察均裁剪到剩余时间；内层请求不得隐式延长外层窗口。该限额用于有界复测，不是传感器物理时限。旧草案与检查结果保留，冻结时以 profile.json 和当前 harness 为准。

评分修订 r8：DS000459 v1-06 第17、26页分别给出 application 与 bootloader 寄存器表，第18页给出 FW_MODE。boot 模式对仅 application 可用的邮箱执行数据访问，报告 PROTOCOL 违规；仅选择指针不等于访问数据。该检查不臆造器件对非法操作的 ACK/NACK 响应。新增模型自检验证 boot 下 STATUS/HW_ID 可读、application 邮箱数据访问被拒绝、APP_START 后合法配置可行，以及尚未建模的可选 ENV_DATA 仍单列 model_unsupported。原候选、参考、公开输入和核心用例集合不变。
