# DHT20 v2 原始依据与边界

本页仅供宿主审计，不能进入 agent 输入。依据是 ASAIR/Aosong DHT20 V1.0 May2021、该文档引用的厂商原始例程、实际 Tock HIL 与固定集成。原参考是正控制，不是 oracle。旧 v1 原件和 97 项结果保留。

| 检查族 | 依据、允许差异与处置 |
| --- | --- |
| DHT-ABI | board.patch 中 component 分配 7 字节、注册 I²C/Alarm/Temperature/Humidity client，调用 startup 一次。实际 sensors.rs:10–36 定义温度 centiC、湿度百分之一百分比。既有消费者处理温度 Err 与湿度标量。只约束真实调用，不强制公开 BUFFER_SIZE、startup 返回值或同步 callback 重入。 |
| DHT-CONFIG | 精确型号 DHT20、I²C 0x38、温湿度单次采样、CRC 开启，沿用原功能范围。CRC 是必要产品配置选择；文档 p10 §7.4 明说可选，不能声称任意 DHT20 应用都必须检查。没有把 CRC 多项式、读取长度、状态位或恢复步骤写入配置。 |
| DHT-NUMERIC | 文档 pp10–11 的 20 位打包和比例，目标单位由 HIL 定义。Fraction 独立计算，比较 abs(output × 2²⁰ − exact numerator) ≤ 2²⁰，允许截断、四舍五入和等价约分。只在额定 −40..80°C、0..100%RH 范围评分；编码端点仍作 oracle 自检。完整 usize 湿度不能截成 i32 掩盖回绕。 |
| DHT-DATA | §7.4：状态字、两个 20 位量及全帧 CRC。状态轮询和读后丢弃 BUSY 帧均支持；部分读取可探测，但不能单独证明 CRC 开启条件下的数据完整性。采集到的有效帧可跨通道复用，不要求每次新转换。后续传输/CRC 错误不自动抹除之前真实获取的值。 |
| DHT-TIME | p9 §7.1 与 p10 §7.4：上电需 100ms、初次状态检查后等待 10ms、测量先等待 80ms 并继续查看 BUSY。80ms 不是完成时间上界；80/100/150ms 为有限模型刺激。核心从已上电稳定状态开始，不能从 new() 时刻另算 POR。不同充分等待、状态轮询和帧轮询均可。初次 10ms 与厂商恢复内部约 5/10ms 分开处理。 |
| DHT-RECOVERY | p10 §7.4 明确 mask 0x18 及 1B/1C/1E 恢复；具体步骤委托官方例程。已保存原始厂商 JH_Reset_REG/AHT20_Start_Init（UTF-8 核对副本 454–502 行）：写零、读三字节、保留后两字节、B0 OR 地址回写。顺序可变。例程“约 5/10ms”不是精确芯片最小时间：提前读取/回写记 model_unsupported，而非物理错误。返回字节为可变模型刺激，不是要求候选复制某个常数。对不同原文支持的恢复机制可扩展模型，但不依靠参考输出轨迹裁决。 |
| DHT-ADDRESS | p9 §7.3 与厂商例程读地址 0x71 共同证明它是 7 位地址 0x38 加读位；不能当寄存器 payload。p10 的 “sending 0x71” 表述含糊，S 中原 Zephyr 也使用寄存器辅助 API；将此作为原始材料冲突记录，不能把人工纠错提示塞入输入。 |
| DHT-CRC | p10 §7.4 对全六字节计算 CRC。独立多项式长除法，并与另一 shift 实现和 65,536 组打包数据交叉检查。故障在首次有效帧前注入，分别破坏状态、共享半字节、温度、湿度和 CRC；未实际读取到注入字节记 not_exercised。核心是有界“不交付未经完整性验证的数据”，不要求唯一错误码、立即回调或一种恢复策略。 |
| DHT-CALLBACK | 真实 HIL/消费者需要对应请求的结果。重复、错通道、同步拒绝后回调是错误；健康请求被拒或不能完成记 not_completed。并发可拒绝或排队。移除精确 OFF/BUSY、强制全局 idle、startup 幂等和强制回调内立刻重入。 |
| DHT-PROGRESS | 请求 500ms、初始化 800ms、稳定输入进度 2s、回调后最多 10ms 观察、单次推进 50,000 事件、进程 5s/编译 300s 都是宿主监督政策。进度窗口传到每次 sample，不允许内层再借一个完整窗口。通过其他通道预热后重复同通道，检出永久缓存，允许有限复用。超限不等于 datasheet 违例。 |
| DHT-FAULT | 传输错误、永久 BUSY、校准不恢复、重复启动旁路报告，不把一种参考错误恢复策略当芯片要求。原故障场景的合理回调安全检查仍保留；诊断完成不等于完整恢复通过。未建模命令、重叠转换或不确定厂商恢复时序明确标记 model_unsupported。 |

D 的资料缺口需要如实保留：datasheet 指向厂商例程，但没有刊出完整恢复步骤。S 有实际源代码，包含相应流程及可能的错误；SD 同时有这两类资料。原始厂商 C/H 只在宿主评分依据中保存，不加入 D/SD 的文档包。要求有原始依据与某一资料条件信息不足是不同问题；不能为了 D 方便而删掉初始化功能，也不能用人工步骤补齐 D 后继续称纯文档。

新分母为 58 核心、22 诊断、3 模型自检。97 个旧检查逐项映射和隐含断言处置见 benchmark/basis_v2/dht20.json。模型是有边界的数字模型，没有真机精度、电源波形或任意合法实现全覆盖结论。厂商例程中的约数时序仍需真实器件证据扩大支持，现有四个提前访问控制必须显示不支持而不是错误。
