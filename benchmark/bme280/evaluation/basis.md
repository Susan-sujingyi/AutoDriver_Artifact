# BME280 v2 评分依据与边界

此文仅供评测维护，不进入 agent 输入。v1 和原参考保持不变。

设备依据为 `benchmark/materials/bme280/datasheet.pdf`：封面标为 1.24、2024-02，内页页脚仍印 1.23；按实际文件哈希识别，不混用另一个在线版本。接口依据为冻结 Tock 的 `kernel/src/hil/sensors.rs`、I²C HIL、temperature/humidity/pressure 消费者以及 BME280 component。已有 board.patch 只把气压消费者绑定到 BME280，没有设备寄存器操作或补偿算法。

S 提供原始源代码、生效宏和真实依赖；D 提供原始文档；SD 同时提供两者。所有条件均提供同一实际 Tock 工程和物理配置。S 中没有手册不能否定有依据的设备要求；旧合同自身也不能成为设备依据。逐项文件哈希、断言处置和旧新用例映射保存在 `benchmark/basis_v2/bme280.json`。

| --- | --- |
| BME-ABI | 真实 component 分配 26 字节、注册 I²C/Alarm 客户端并调用一次 startup；消费者使用三个 sensor HIL。保持实际编译约束，不强加 startup 返回类型、公开缓冲常量或反复启动策略。 |
| BME-CONFIG | 本实例沿用 forced、T1/P16/H1、filter off；手册 §3.3、§3.4、§5.4 定义模式和字段。在实际触发时核对生效字段，不要求固定写入顺序、重复写默认值或读 ID。 |
| BME-DATA | §3.3.2、§4、§4.1：完成的结果保留到新结果产生；新测量进行中仍可读取先前完成的结果。原模型在新转换开始时就替换输出，且禁止所有测量中读取，予以修正。同步 forced 模式可合法分笔读取，不强制 8 字节一次传输。每个成功通道仍须有完整的原始测量及所需温度输入证据，不能把复位占位值当测量值。 |
| BME-NUMERIC | §4.2.2/Table 16 的校准布局和符号；§4.2.3 定点补偿、§8.1 double、§8.2 32 位压力替代算法。目标 HIL 明确 centi°C、百分之一 %RH、hPa。oracle 计算各条文档算法及相邻整数舍入的有限包络；这不是传感器物理精度容差，也不要求照搬参考算术路径。校准可延迟到需要时读取，不要求初始化阶段读完所有系数。 |
| BME-CALLBACK | sensor HIL 及实际消费者：成功提交的健康采样需要相应通道结果，拒绝不能凭空回调，重复/非请求通道回调不能消耗不存在的请求。并发可拒绝或排队，不锁定 BUSY。BME 消费者没有 APDS 那样在回调内部立即执行下一请求，因此不照搬 APDS 的回调内重入硬要求。 |
| BME-PROGRESS | 检查稳定输入变化最终能体现在读取结果中，允许跨通道共享、缓存和后台事件。2 秒稳定输入窗口、50000 事件和进程限额是评测监督策略；窗口内不完成标 not_completed，不声称违反芯片或 HIL 的响应期限。 |
| BME-FAULT | I²C HIL 有同步提交错误和异步完成错误；允许重试、已有有效缓存和合法错误回调。HumidityClient 无错误值通道。故障结果、到达性和恢复策略单列诊断，不把一种参考恢复政策写成公共 API。异常设备超过文档最长转换时间的永久忙故障也是诊断；不能因此错误拒绝使用充分固定等待的合法驱动。 |
| BME-MODEL | 已上电并完成初始复位才创建驱动。软件复位后 NVM copy、测量时间按 §5.4 和 §9.1 建模；T1/P16/H1 的最长转换刺激为 43.8ms。§9.2 指出过快 forced 请求使数据率饱和，模型不因第二次写触发就无限重启测量。没有依据的配置中途生效行为标 model_unsupported，不能以模拟器不支持为由判候选错误。 |

v2 分母为 **28 核心、17 诊断、3 模型自检**。核心包含 21 数值条件、3 并发、3 稳定输入变化和1跨通道采样。诊断的 pass 只表示该观察执行完成，不是对应故障恢复功能全部正确；诊断失败也不能隐藏。核心全过不能表述为通过全部运输故障或真机验证。

42 项旧用例都在 JSON 中有去向：数值21项修订共用模型；BUSY3项改为并发；12项故障迁至诊断并由 Trigger 改为实际首笔/数据位置；3项永久忙改诊断；初始化 BUSY 政策移除，由正常启动/采样覆盖；跨通道1项拆分缓存与稳定变化；错误 ID1项改诊断。新增加的变化观察与模型自检单列，不掩盖分母变化。

模型仍是有限数字接口模型。测量开始时固定本次物理输入，单个 I²C 完成事件内原子读取；并未模拟逐位总线跨转换的全部相位。当前输入变化用例在同一校准芯片上进行，校准变体分别冷启动。所有补偿控制及参考只是正反控制，不是评分真值或生成成绩。验收证据及冻结状态见十三题总报告和任务 freeze.json。

稳定输入进度监督进一步明确为 2000000 µs，与单请求完成窗口分开。绝对截止时间传入每次采样，轮询与回调后观察均裁剪到剩余时间；内层请求不得隐式延长外层窗口。该限额用于有界复测，不是传感器物理时限。旧草案与检查结果保留，冻结时以 profile.json 和当前 harness 为准。

## 冻结 NuttX SIM 迁移（开发验收，尚未发布）

I²C 与 SPI 使用 `nuttx/sim/` 下同一设备模型和场景，分别接公共原生
I²C/SPI vtable。没有替代 OS 头文件、互斥、延时或 Sensor 实现；通过实际
`open/read/close` 和真实 Sensor 上半部运行候选。设备代码在候选隔离编译后才参与链接。

两道 NuttX 任务的公开 `driver_api.h` 明确要求每次 fetch 获得 fresh forced
sample、上限 1 秒，因此必须有本次调用期间完成的转换及本通道所需完整原始数据；
该约束与 Tock 接口允许的跨通道缓存规则不同。模型不要求可选 ID 探测、特定触发次数、
固定读取顺序，或把 SPI 命令和数据合成一次 exchange。forced 的 01/10 均可用；
压力过采样编码 101/110/111 均代表 x16。只有 SPI mode 来自对应任务，不能同时接受其他模式。

设备行为依据同一包内手册 §4.1、§5.4、§6.2/6.3、§9.1：
转换期间保留旧输出；转换完成更新全部输出；输出 burst 期间锁住被读取的帧，
I²C STOP / SPI CS 上升沿后解除。重复 forced 触发不无限延长正在进行的转换。
多字节写入按地址/数据对处理，读取才自动递增。ctrl_hum 在 ctrl_meas 写入后生效。
软件复位恢复配置与无效初始输出，并模拟 NVM copy。正常测量采用 43.8 ms 上界刺激。
转换中途改变配置、未建模寄存器等明确返回 model_unsupported，不归责为候选错误。

每题当前 32 项核心：21 个数值/通道组合、输入变化、生命周期、无效 factory、
传输错误、无效压力校准、3 个真实节点冲突清理、3 个 skipped 原始数据检查。
2 项模型自检：独立数值 oracle（Decimal 交叉验证、Bosch T/P 示例、4096 对有符号
湿度系数编码），设备输出 shadow 与 forced 饱和行为。
永久 busy 和 NVM busy 单列 2 项诊断，不强迫使用固定等待的实现采取某一种轮询恢复方式。

模型按字节推进总线时钟，但不模拟模拟电气波形；没有把通过解释为真机验证。
allocator 故障注入和所有并发生命周期仍需公共平台覆盖审查，不能由上述节点清理测试推出。
原参考源码、输入配置、上层应用和既有固件均未修改。
