# APDS9960：评分依据审查与精简输入原型

2026-10-06。本次完成原始依据审查和 S/D/SD 输入原型，不修改 v1 评分、参考实现、方法、知识库或历史成绩，不运行模型或真机。

**结论：不能只删掉专家提示，然后直接沿用全部旧断言。** APDS9960 的 34 个行为用例中，25 项建议保留测试目的并修订，9 项建议降为诊断。这里统计的是旧用例处置，不是新通过率、新版分母，也不是“34 项旧测试全部无效”。旧版事先公布了较强的合同；本次审查针对用户要求的新版任务边界。

## 依据和边界

原始设备依据是 artifact 内冻结的 [AV02-4191EN PDF](../benchmark/materials/apds9960/datasheet.pdf)，不是旧 contract、模型提取结果或参考实现。页码均指 PDF 的印刷页码。实际目标依据是冻结的 [Proximity HIL](../third_party/tock/kernel/src/hil/sensors.rs)、[I2C HIL](../third_party/tock/kernel/src/hil/i2c.rs)、[Proximity 上层 capsule](../third_party/tock/capsules/extra/src/proximity.rs)，以及准备后工程中真实存在的板级调用。

板级调用由已有 [board.patch](../benchmark/public/apds9960/board.patch) 安装。它是 benchmark 提供的固定接线环境，不能称为未修改的原版 Tock；它确实约束构造器、资源和客户端接线，但并不自动支持旧 contract 里的所有额外要求。源驱动及 Zephyr binding 用于追溯源配置；源实现存在错误的可能，不能作为唯一正确性标准。

完整的逐用例映射、21 组共同/专用断言、源文件 SHA-256、条件可得性见 [scoring-basis.json](../runs/audits/apds9960-input-v2-20261006/scoring-basis.json)。原文第 9、23 页同时做了图文核对，图像保存在同一审计目录。审计不是形式化验证，也没有证明模型对所有合法实现完整。

**原始依据成立，与某一资料条件是否提供该依据，是两件事。** D/SD 提供厂商文档，S 不提供。不能因为 S 没有手册就删除设备正确性要求，也不能为了让 S 容易答对而把手册结论写成用户提示。S 是否足以解决原源码缺陷，应由资料价值实验回答。

## 共同断言审查

很多“数值用例”先调用同一个 `init()`，再调用 `assert_success()`。这些助手还要求读 ID、100ms 完成、严格新一代样本、总线/Alarm 全部静止等。因此不能只审查 `cases.json` 的 11 个数字。

| 检查内容 | 原始依据/实际调用 | 新版处置与合法实现范围 |
| --- | --- | --- |
| 类型、构造器、I2C/Alarm/Proximity 客户端、3 字节资源 | 实际 component 和 HIL；旧 harness 278–319 行 | 保留实际工程编译要求，让 agent 从真实工程发现接口。 |
| 必须导出 `BUFFER_SIZE = 3` | 旧 harness 第 12 行；实际 component 直接分配 `[u8; 3]`，没有引用该符号 | 删除额外导出要求。缓冲区真实容量仍是固定接线约束。 |
| `startup()` 必须返回指定 Result、重复调用成功 | component 只执行一次 `let _ = startup()`；其调用本身未约束返回类型 | 保留可调用的实际接口；不能据此推导精确返回类型或幂等策略。重复启动先作诊断。 |
| 接近度值、0/255、符号和单位 | PDF 11、25、26 页；HIL 120–125 行 | 保留 unsigned 8-bit 原值语义，不引入距离/百分比换算。寄存器/公式答案留在评分侧。 |
| 增益、脉冲、LED、偏移、光电二极管配置 | 明确的目标物理配置；PDF 20、23、24、26、27 页 | 保留有效字段。新版配置仅写 2x、8us×8 等物理选择，不写寄存器值或源 bug。 |
| 非活跃字段 | PDF 的各字段使能条件 | 不要求 ALS gain、CPSIEN、WLONG、无效 SAI 等必须与参考一致；旧测试对此已有部分容忍，应保留。 |
| 配置与使能顺序 | PDF 20 页注释 | 保留活跃引擎的合法配置时机；接受不同合法顺序、RMW 和不重复写默认值。 |
| CONFIG1 保留位及复位值 | PDF 19 页为 0x60；23 页表和注释支持 bit6/5=1，但首句写 0x40 | 写入保留位的说明与复位值歧义分开。不能把未重复写默认值判错；0x60 有依据，但原文不一致必须记录。 |
| 5700us POR、7000us exit、1200us 周期 | PDF 9 页状态图及 11 页近似时间表；1200us 是旧模型取值 | 图 7 的退出条件还包含模拟引擎使能；旧模型仅按 PON 上升计时需修正。启动时刻与设备上电时刻分开，不宣称名义时序是精度保证。 |
| 100ms 启动/请求上限 | 仅旧 contract 与模拟器 | 从设备语义中移出。执行仍需有界，但超出观察窗口单列“未在窗口内完成”，不能自动解释为违反原始设备/接口规约。 |
| 每次初始化必须读 ID | PDF 25 页定义 0xAB，但未要求所有集成驱动必须运行时探测 | 正常 0xAB 设备必须可用；强制探测、错误 ID 恢复与 0x9C 兼容先作诊断。 |
| 成功回调与错误值 | HIL 标量 callback；上层按回调完成请求 | 保留成功数据投递，不把错误伪造为合法 0。不能因此禁止一次总线失败后重试并返回真实有效值。 |
| 结束时不允许任何 Alarm/总线活动 | 旧 `idle()` 辅助断言 | 改为资源安全和上层进展；连续轮询可有后台活动，不能一律要求全局静止。 |
| PVALID、PDATA 清有效位、PINT 区别 | PDF 11、25 页 | 保留有效数据语义；不能规定必须某种 STATUS 读取轨迹。已有未读有效样本可用，合法等候下一次转换也可用。 |
| 每个请求必须消耗严格更新一代转换 | 旧模型 generation；HIL 写的是最近读到的值 | 不直接提升为接口规范。拆分数据有效性、连续采样响应和缓存/合并策略，评测不同合法调度；读取后新转换可重新置 PVALID。 |
| 初始化前 OFF、初始化/采样中 BUSY | HIL 无此精确声明；上层 capsule 的 BUSY 是应用队列语义 | 验证请求不被破坏或无故丢失；不把 wrapper 的错误码直接套到驱动。 |
| 回调内再次请求 | 上层 capsule 253–285 行，在 callback 内调用 `run_next_command()` | 有实际消费者依据，应保留；独立去除严格 generation/全局 idle 等附加限制。 |
| 不支持中断必须 NOSUPPORT | 中断采样未选；HIL 未指定该错误码 | 记录诊断，不以一个未选功能的特定错误码计主功能成绩。 |
| 注入总线错误后必须无回调，并同步返回 public read 错误 | I2C 提交有同步结果，完成有异步结果；public read 不必立即提交总线 | 允许延迟提交、透明重试及真实成功。保留资源/伪造数据检查；HIL 缺少异步错误通道的限制不能靠要求一个参考恢复策略掩盖。 |
| 地址保持及清中断写法 | PDF 8 页描述读取使用前次寄存器地址；33 页给出 address-only clear | 地址保持有原文依据；额外 dummy zero 是源兼容容忍，不是厂商已证明合法行为，分开记录。 |

配置来源也需要诚实区分：原型沿用 v1 已选的物理参数，是当前任务实例的选择，并不宣称每个真实用户都会提供这么多字段。源宏配置只用于指定所附源代码的构建分支；目标配置用于明确本次功能，二者不复制同一份 YAML。以后可以选择更少参数并接受默认值，但必须相应扩大评分允许范围，而不是暗中保留旧固定值。

`cases.json` 的 6 个非法 JSON 输入，以及 oracle 遍历全部 256 字节的测试，是 oracle 自检，不是另 262 道驱动用例。板级编译、capsule 编译、patch 范围和硬件状态在 JSON 的 `non_behavior_checks` 中单列；真机仍未验证。

**下一版评分不能只删除 9 项，然后声称剩余 25 项已经成立。** 应先修正共同模拟器和助手，使用合法替代实现验证不会误拒绝，使用故障控制验证仍能识别错误，再冻结新分母。参考实现通过只能证明这个实例通过。

## 精简输入原型


| 文件/目录 | S | D | SD | 内容 |
| --- | --- | --- | --- | --- |
| prompt.md | 有 | 有 | 有 | 两段开发请求和 patch 交付要求 |
| configuration.yaml | 同一份 | 同一份 | 同一份 | 设备、板、总线、所选功能、物理参数及可改路径 |
| materials.json | 有 | 有 | 有 | 路径、版本、内容哈希；无函数入口/正确答案映射 |
| target/ | 同一基线 | 同一基线 | 同一基线 | 实际 Tock 工程，固定接线；既有统一材料政策剔除目标设备实现 |
| source_inputs/ | 有 | 无 | 有 | 原始选定 C 文件、一份源宏配置；不附未编译历史头文件 |
| source_os/ | 有 | 无 | 有 | 完整固定 Zephyr 快照；真实被 include 的头文件就在其中，不重复复制 |
| datasheet/ | 无 | 有 | 有 | 原始 PDF、原文文本、页码映射；无人工摘要、bug 提示或答案 |

不包含旧 `public/contract.yaml`、`task.yaml`、`task.md`、专家冲突说明、参考实现、隐藏用例、人工 ABI 指南或编译产物。host/ 保存来源、基线、输入文件清单和哈希；不能给 agent。S/D/SD 的 target 相同，源条件只影响原始材料，配置不随方法变化。

这是可检查的输入准备原型，**尚未接入 G/E/A，也未替换旧评分器**。目录里没有自动形成 OS 隔离；将来必须按现有独立 UID/Landlock/网络限制交付 agent/，不能让 agent 从父目录访问 host/、本审计或历史结果。K 没有修改；也不能宣称现有 E 适配器已经消费了新输入而没有补回旧合同。
