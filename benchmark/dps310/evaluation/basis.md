# DPS310 v2 原始依据审查

宿主审计资料，不进入 agent。依据为 Infineon DPS310 V1.2、2020-10-15，厂商 sensor-xensiv-dps3xx 原始实现及实际 Tock 接口/接线。原 v1 与参考不修改；旧 120 项成绩保持旧身份。

| 检查族 | 依据、实现自由与处置 |
| --- | --- |
| DPS-ABI | board.patch 分配 18 字节并连接 I²C/Alarm/Temperature/Pressure，startup 只调用一次。实际 HIL 定义 centiC、hPa。固定集成编译约束真实接口；不要求私有常量公开、startup 精确返回值、幂等或同步回调重入。 |
| DPS-CONFIG | 保持 DPS310、I²C 0x77、command acquisition、T/P 8x、FIFO/中断关闭。pp28–33 PRS_CFG/TMP_CFG/MEAS_CFG/CFG_REG 和 p15 scale 表支持字段判据。8x 不需要 shift。背景模式下的速率字段在命令模式下可不同，未使用的中断极性可不同。TMP_EXT 按实际出厂 COEF_SRCE 匹配，不强制某一读取调用。 |
| DPS-NUMERIC | pp14–15 多项式，p37 校准位图：signed12 c0/c1、signed20 c00/c10、signed16 其余，ADC signed24 MSB-first。独立位流解码、Fraction 多项式与 Decimal Horner；8x 的 kT/kP 为 7864320。回调距精确量最多一个目标整数单位，允许 f64/f32/整数等价路径；不得直接除以8或复用另一 OSR 比例。 |
| DPS-RANGE | 正常评分沿用处于器件额定物理范围的合成 ADC/校准见证。零与负值不是 FIFO 关闭时的无效标记。任意位宽极端或非物理校准组合仅作 oracle 检查，不声称真实出厂系数分布或测量精度。 |
| DPS-DATA | pp24–27 数据读取后保留，p32 ready 清除不等于 DATA 失效。完整通道可一次或分笔获取。温度和压力是独立命令转换，不是必须同 epoch 的同时帧。只要求用于数值计算的量有实际完整采集依据；不要求每次请求产生新转换或所有 trim 每次读全。 |
| DPS-CACHE | p14 §4.9.1 明确温度可能未在最近压力测量之后重测；p12 只说明一起测量补偿更准确。删除 v1 人工一秒缓存上限、必须使用最新温度及失败必清缓存。允许有效温度重复用于压力、多秒缓存和 T/P 任一先后顺序。稳定输入改变后仍检查补偿能在有限观察中反映变化；5s 是监督政策，不是假称厂商精度/缓存寿命。 |
| DPS-BOOT | Table8/启动图及 p32 说明 2.5ms 寄存器访问、SENSOR_RDY/COEF_RDY。明确模型采用 Table8 的12/40ms；默认已上电稳定，另有冷启动用例。系数未就绪时值未定义，提前读取归 model_unsupported，而非把任意零值作为真实芯片输出。可轮询或充分等待，不能强制唯一判断式。 |
| DPS-TIME | 8x 的 14.8ms 是表格测量时间，不单独证明硬最大值。增加30ms慢完成刺激，接受等待与轮询。未定义重叠命令不强制参考恢复流程，归不支持；命令完成返回 standby、保留数据。ready 清除的具体字节点未明确，默认模型在通道末字节清除，报告这一边界。 |
| DPS-BUS | 原文 I²C 自增读写，允许重复START或STOP后读、连续配置写、分段校准和分通道读取；共享半字节和符号由原始位图决定。未知保留字段、未建模地址和操作语义不能直接算已证实协议错误。 |
| DPS-WORKAROUND | Infineon commit 86b33708970e7f3f4c3035a90d7b87e7d5b7186b 的 _xensiv_dps3xx_correct_temperature（369–398行），在配置出厂温度源后调用（636行）。它证明厂商采用了此写序列；现有 PDF/源码未解释受影响硅版本、必需条件、遗漏的温偏或其他等价修复。旧合同“选中设备必须执行”没有额外器件身份实证。故 trace/重新锁定仅旁路记录，不能以缺少序列直接判数值错误，也不往 D 放专家步骤或厂商C。三个 omission/value/relock 控制只证明该审计未干预主评分，不能称物理合法实现；是否需要该修正仍有硬件/厂商说明缺口。 |
| DPS-IDENTITY | 型号固定不等于驱动必须读取 revision/product ID。保留正常器件0x10，0/11/FF仅作策略诊断，不强制拒绝某个非任务器件。 |
| DPS-CALLBACK | 检查接受请求对应回调、通道、值及所有权；重复/错通道/拒绝后回调为错误，健康拒绝或不完成为 not_completed。并发可拒绝或排队；不强制 OFF/BUSY、全局idle、同步重入或每次故障一种错误通知。 |
| DPS-PROGRESS | 请求500ms、初始化150ms、稳定输入5s、回调后最多5ms、推进50000事件、单进程5s、构建300s为宿主监督预算。内层请求使用外层绝对截止时间。同通道重复和只请求压力时的温度变化分别检查长期不更新。 |
| DPS-FAULT | 温/压命令、状态、数据及初始化的可达注入点逐项报告。错误不能抹除此前实际采集的值；无接口依据时不强制重试、清缓存或一个精确错误码。诊断成功只说明已执行观察，不证明全面恢复；没有执行到注入点为 not_exercised。 |

三种输入的必要配置、目标、可修改范围完全相同。S/SD 保留源代码中原有修正步骤与可能错误；D/SD 保留原 PDF，缺少厂商未公开寄存器的修正序列不能用人工合同补齐。资料充分性须分开报告：D 能支持主公开协议/补偿，不能据此证明隐藏修正适用性；S 中出现该序列也不自动成为独立物理真值。

当前 72 核心、44 诊断、3 模型自检；完整旧新映射见 benchmark/basis_v2/dps310.json。通过该软件评分不等于所有硅版本均已处理厂商温度问题，也不等于真机精度或应用可靠性已验证。

## NuttX SIM 开发评分适配

`nuttx/i2c/sim` 使用真实冻结 OS、Sensor、文件接口和公共逐字节 I²C 时钟。
共享 Fraction/Decimal oracle 提供 30 个数值向量、2 个 oracle 边界向量和混合 T/P
补偿表；校准字节始终固定为该次启动的芯片配置，稳定输入测试只在相同校准 profile
内改变原始量。原生公开 `driver_api.h` 明确了 NuttX 特有的 100ms 操作时限、
每请求通道的新转换、最近有效温度、一秒 T/P 间隔和失败温度采集失效规则。
这些有意冻结的产品要求与上文 Tock HIL 的缓存自由度不同，不能通过迁移评分放宽。

设备模型不要求可选身份探测、唯一事务顺序或 factory 中读完全部系数。
厂商私有温度修正只作 trace 观察，不把参考序列作为通过条件，也不假造遗漏时的温偏。
真实节点冲突测试检查部分注册回滚及重试；逐字节错误注入检查温度缓存失效、
调用者输出不变与总线释放。独立温度、压力转换的已完成帧和已采集见证分别维护，
未读取的新帧不会凭空替换有效缓存。校准未就绪、未定义重叠命令或未建模寄存器
归 model_unsupported。数据在 ready 清除后仍保留；末寄存器清 ready 是明确的模型边界。

开发用例为 120 个数值/通道/出厂温度源组合，加输入变化、慢转换、生命周期、
运输错误、温度缓存失效、2 个真实注册冲突和6个部分读错误，共133核心；
永久 busy 单列诊断。独立 oracle 和已采集温度见证是模型自检。
当前接入不代表发布门已通过，更不代表硬件或全部调度竞争情形得到验证。
