本次任务：根据给定要求生成目标操作系统的传感器驱动候选代码。

设备行为模型（DBC）说明必须保持的设备及采集行为；目标接口说明（FP）说明可用的操作系统能力；实现对应方案（BP）说明两者如何连接。这三份输入都是本次只读要求。你还会收到公开集成要求、当前内部检查发现以及待修改文件的完整内容。

本阶段默认提供这些完整父对象及必要目标材料。框架原文仍在同一获准资料池中，需要额外声明或实现细节时，使用实际列出的有限工具按需查询；来源闭包审计不表示所有祖先全文都在本次 context 中。不能引用未实际提供的片段或依靠记忆补 ABI。

当前允许实现的范围在 call.generation_scope 中；host_generation_gate=open 只表示本次允许生成候选，不表示代码正确。editable_paths 是允许改动的文件/目录，base_files 给出已有文件的当前内容 hash。

按给定对应实现初始化、设备操作、计时、数据验证、资源持有/归还、样本提交、请求完成和失败处理。可以选择目标代码自己的函数与内部状态，但不能改变设备策略或父要求。初始化请求已接受不等于设备已准备好；失败和过时事件的路径也需按要求处理。如果某个只读父要求存在阻碍实现的缺口，报告并请求补充，不自行改写它。

返回候选文件修改，已给输出模板固定了 kind=code 和 format=file_edits。在 artifact.edits 中为每个文件填：
- path：相对工作区、以 target/ 开头且位于允许范围内的路径；
- operation：create、replace 或 delete；
- base_sha256：replace/delete 使用当前基线 hash，create 为 null；
- content：create/replace 的完整文件文本，delete 为 null。
同一路径只能出现一次，create 不能覆盖已有文件。

基线清单明确不存在的驱动由你依据父契约和公开 ABI 新建；目标中没有该器件实现并不是缺失输入，不要求先获得一份现成目标驱动。不得请求同器件的目标参考实现。可以自行设计内部状态和函数，公开集成签名及父契约保持不变。需要查询获准原文时，仅通过 context_requests 返回请求；调用已列出的工具时 scope=internal_tools、query 为含 tool 和 arguments 的 JSON 字符串，不在响应外输出调用参数。

只在执行环境实际提供相关工具时使用获准的编译/内部检查。编译成功不能代表全部设备行为正确。不要修改输入契约或输出最终提交清单；主机将在准备副本上重新检查基线、应用候选并生成规范提交。用证据引用说明关键实现依据，保留未完成范围。
