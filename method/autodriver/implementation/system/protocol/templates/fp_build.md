本次任务：从操作系统接口资料中，恢复一份可供生成驱动使用的“框架接口说明”。

背景：不同操作系统会以不同方式提供总线传输、定时、传感器接口和缓冲区。仅知道函数名称和参数，不足以正确使用它。我们还需要知道调用前提、接受与拒绝、完成时刻、错误返回以及资源归属。这份信息称为 FP（Framework Profile），只描述操作系统框架，不描述某个传感器的命令和测量流程。

请阅读实际输入中标为“操作系统接口的原始声明、文档或实现”的材料；如有版本/配置说明或已有候选，一并核对。只恢复本次具体目标要求的接口，不能把一个传感器专用辅助函数当作通用框架保证。

对每个相关接口确定：
1. 调用前需要满足哪些条件，参数及长度允许什么范围。
2. 返回什么才表示请求被接受，什么表示立即拒绝。
3. 它是执行完成后返回，还是接受后稍后回调；如果使用回调，回调参数、触发条件和调用上下文是什么。
4. 调用前后谁可以访问缓冲区，成功、拒绝、失败及取消时由谁返还它。
5. 物理传输结束与软件返回/回调有什么有据关系；未知就明确未知。
6. 时间参数和输出数值的类型、单位、比例、范围及错误表达能力。

用接口声明确定类型，用文档和实际提供该接口的实现确认非平凡保证。存在一个回调函数不能证明每个请求恰好回调一次；函数阻塞也不能单独证明物理传输已结束。宏和常量不能求值时请求解析，不猜数值。

输出一份 FrameworkProfile 声明式表达式。os 与 snapshot 记录输入给定的操作系统、版本和配置；相关能力放在 capabilities 或已定义的专用槽；假设、缺口分别记录。具体字段及构造器的完整定义就在本消息后面的语言说明中。将表达式字符串放入已给响应模板的 artifact.content，并填写证据引用；本次不修改操作系统仓库或发布共享知识库。
