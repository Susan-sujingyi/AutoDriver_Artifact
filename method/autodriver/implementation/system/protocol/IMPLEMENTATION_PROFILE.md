# 语义文档实现约定 v0.2.0（开发中，尚未发布）

FP、DBC、BP 的首要产物是实际模型返回的可读语义文档，允许文字、表格、伪代码和结构化数据。主机固定阶段、对象、来源及父版本；契约格式、引用重述或未证明的进展义务均不再作为代码生成准入条件。通用语义说明统一覆盖来源与策略、全局控制、事件时间、错误重入、校准及样本生命周期、物理计算与数值编码、框架保证和绑定、条件进展。器件实例和历史失败答案不进入说明。

文档可附一份派生可执行视图，使用下述已有构造式语言及现有内核。缺失、不可解析或歧义视图明确记 unsupported/not_checked；可解析视图的确定性违约和 unknown 如实保留，视图与原文的语义蕴含仍未验证。可用时执行已有原生方法检查，不将编译、有限执行或内部符合性称为独立评分或硬件通过。不存在格式修复循环，也不伪造旧版 open gate。

代码编辑仍检查实际允许路径、原始基线和完整文件载体。公共编译、有限内部检查及修复采用相同的 5 次候选检查和累计 4 次代码修复请求上限。预先固定提交最后一次实际应用的候选；后续修复失败时保留该版本及实际父绑定，不选择历史最佳结果、不继承已失效证明。模型、上下文、时间和费用边界不变。独立评分仅在主机冻结后执行。

以下 v0.1.x 记录解释既有构造式语言和旧生产流程；旧流程及失败凭据保留，不代表当前文档路径仍要求其中的准入与响应格式。

本说明补足 v0.1 构造器目录的具体值表示。传输 schema 标签仍为 v0.1，构造器集合为 110 项；`generation_mode` 是可信主机请求字段，不由响应设置。它不改变设备要求、框架保证或原始证据。

v0.1.24 将错误、未提供或不可作为事实的引用统一保留为不可信原始响应，并进入原有有界 envelope repair；`needs_evidence` 的空 artifact 不再使引用拒绝成为未捕获异常。索引、候选与诊断仍不可引用为事实，修复诊断的来源目录也排除不可引用材料。代码/上游候选修复在协议或额度处停止时保留异常类型、原因和已有界限，拒绝与修复额度不变；这些记录不反向补写历史异常。

v0.1.23 的 inspect_symbol 支持1至16个精确符号选择器：单名、空白分隔名称或显式数组。查询做同一有限声明/类型/调用闭包，不猜测拼写、命名空间或provider。完整闭包、边界和缺口留在工具审计；实际调用收到非事实查询索引及完整原文片段。找不到符号时保留缺口；较小作用域同时给出完整精确名称目录，超过128个名称则明确省略目录并提示使用原文检索，不以部分目录推断不存在。source_index、framework_index 仍不可引用为事实；代码调用可以读取这种机械源码索引，不获得额外语义保证或内部候选符合性反馈。原材料、上下文/工具/修复额度、消融控制和规范父对象保持原有边界。

v0.1.22 在固定上下文字节上限内加入最多三步显式范围重选：大型机械分析可改选完整函数/调用/缺口索引，器件文档和框架原文可改选原资料页码/声明定位索引。新 kind 为 source_index、document_index、framework_index，均保留 hash 固定的原始父资料并标记 evidence_eligible=false；它们不是可引用事实。模型先通过真实工具获取具体未决问题的完整原文或函数依赖闭包；read_evidence_range 按登记材料身份和原始行号读取至多6000行，拒绝范围外资料、契约和非法坐标。已检索的本轮材料保持保护，不再被索引替代。原始器件源码、配置、规范性契约、候选、集成要求和诊断不裁剪。不能满足相同上限时仍明确终止，不增加输出、调用或修复额度。发布状态由 method.yaml 及其实际源码绑定验收决定，本说明本身不授予资格。

v0.1.21 为每个完整上下文片段标记 `evidence_eligible`。FP/DBC/BP 的可引用来源与确定性恢复支持检查使用同一阶段材料规则；候选、诊断及方法说明仍完整可读，但不能作为器件或框架事实的来源。响应 schema 只列出可引用句柄，句柄与旧式材料/行段引用均执行此边界。代码修复保持原有公开编译和内部诊断用途。旧实际消息缺少该字段时按原消息读取，后续支持审计仍保留未知，不反向修改旧凭据。

v0.1.20 代码生成/修复默认提供完整 DBC、目标 FP、适用 BP、公开集成、baseline/候选和检查诊断；框架原文保持在同一获准池、完整来源闭包和真实查询工具中，按需加入所需完整声明/实现范围。默认不复制全部 FP 提取原文，不删除契约/检查或提高固定上下文限额；请求补证仍消耗相同有界调用。

v0.1.19 的 `frame_status.<帧名>.complete_current` 是同一解释器的派生观测元数据，按帧名、本次 instance 和已完成布局/完整性解码确定，不是默认有效性或设备事实。旧帧、缺帧和身份不匹配为 False，校准、物理新鲜性和数值合法域仍由显式来源/状态决定。符号域使用完整布尔范围，不假定 True。requires/domain 的可执行纯谓词及限制见完整 DBC 定义；旧自然语言不被自动翻译或丢弃，仍保持 unknown。构造器集合不增加。

v0.1.18 的生成诊断保留 checks 的所有字段和值，准入对象只在 checks.generation_admission 出现一次，admission_location 明确其位置；JSON 内层使用紧凑序列化，不截断原文、检查或缺口，不提高上下文上限。代码创建不依赖现成同器件目标实现；缺失 baseline 文件明确使用 create。无效代码响应仍是整体不可信文本，凭据核验后的恢复使用 code repair 并累计原有四次修复额度，不把无效文本变成候选。

代码补证从首次 code_generate 转为 repair(code)，同样累计四次限制。空检索返回明确的未命中诊断和获准材料身份清单，材料内容/设备事实不因此补造；它仍受有限补证次数、总请求和时间界限制。

v0.1.17 将当前调用的片段引用缩短为 c1/c2 等局部编号；完整材料 ID、字节 hash、行段及整个实际消息 hash 仍固定，旧 hash 风格句柄按原始消息继续读取。句柄只在本次调用有效，不自动复用旧引用，也不把不存在的引用映射到其它证据。格式诊断列出当前可用来源句柄并明确旧响应中的链接是待修的模型输出，不是可信来源；引用存在仍不证明断言蕴含。

BP 的完整树模板可预填当前唯一可见的只读 DBC/FP/公开集成父材料 Ref 身份，便于准确使用主机已有元数据；不预填映射、设备参数或保证。模型仍须恢复 BP，其引用仍通过当前父版本组合检查。

append 的写入位置现按原列表长度及响应顺序计算，所以多次末尾追加和原有元素更新可以共存；原索引不移动。覆盖整个列表再改其子项、新加 map 后再写其子项、重复替换及其它重叠写仍拒绝；新追加的槽不能冒充原基准中的可替换路径。错误 base ID/hash 给出本次固定模板身份，主机仍不代改响应。此修订只细化确定性的编辑装配，不改公式、有效性或来源保证。

v0.1.16 允许 Lifecycle 用可选 variables 声明同一全局图的显式持久状态；旧调用默认空映射。Sequence 中既有 Assign 可作单步状态更新，使用相同数据环境、类型检查和 SSA 见证，不再要求为保存已读字段而重写整个控制图。源必须支持存储/有效性及失效条件；旧帧本身仍不跨采集有效，也不默认 valid=True。显式 FSM 的并行 effects 与多个顺序 Assign 区别保留。constructor_edits 增加 append，仅在原有列表末尾追加一个值；原索引不移动，不允许删除/重叠或新造路径。主机不生成这些赋值，也不据此声称来源、校准或全路径正确。

字段编辑本身被拒绝时，下一次有界格式修复仍提供未经修改的完整、固定原基准；错误编辑只进入诊断，不作为新的不完整契约，也不按响应自称的 base ID 选择材料。原响应、错误和实际调用数保留，不能据此重置修复额度。

FP 修复对完整作用域做同一标准核验：OS、类型、角色、登记 hash 与实际固定字节必须匹配；有验证的材料别名可以保留并在当前调用完整提供。别名不同不等于作用域变化，内容变化也不能靠别名消除。该修订修复导入 FP 字段修复时的字符串 ID 误拒绝，不扩展原始来源或 provider 保证。

v0.1.15 给同一 FP/DBC/BP 的 repair 增加可选 constructor_edits 载体。仅在当前调用提供唯一、完整、可解析候选时，主机预填其材料 ID 和原文字节 hash；模型按显式 path/value 做有界 replace/add，未修改字段保留。拒绝旧/错 hash、其它对象、根替换、删除、重叠路径、载体保留键以及不存在的 replace 目标。主机只无损装配，不替模型平衡公式括号、补前提、改引用或作语义修复；新证据与未决仍完整提供，结果重过同一检查。旧完整载体继续可读。该修订用于减少重写无关大公式造成的回归，不豁免任何必要义务。

上下文硬界和有界响应修复耗尽现在具有明确方法终态，不作为基础设施故障自动重试；输入漂移、错误保存响应身份、未知程序异常及服务故障仍保留各自异常/恢复路径，不被该分类吞掉。

v0.1.14 增加两项通用语义：FP 的 ElapsedTimeLowerBound 和 BP 的 BindSyncDelay；SyncReturn.delay 为可选字段，旧返回默认 None，不自动获得延时保证。检查同步延时的整数参数域、时间单位、最大提前损失、成功谓词、中断失败策略、精确父 DBC 下界和源 FP 物理完成关系。未知 provider、附加假设、物理上界与候选执行顺序仍分别未决；不把 usleep 当作 TickAlarmContract，也不默认其物理下界。同步成功谓词不从 errno 名称或正负号猜测。

NuttX 内部原生工具支持公开温度、湿度、气压、照度、距离、CO2、TVOC 标量布局，声明从冻结公共头文件机械投影，访问必须通过实际编译。初始化和采集响应来自同一全局图的有界输入见证，支持多个帧及一次 I2C_TRANSFER 中的先写后读；不按已观察错误字节选择“正确”响应。保留每段 flags/length 原生事件，电气 STOP/重复开始及全部分段保证尚未证明。新增可中断 sleep 激励，只有实际调用才记录中断；继续/失败策略依赖当前 BP，不能预设每个延时 API 都可中断。

v0.1.6 统一新调用中的引用和 carrier 说明：outbound response_schema 只要求当前模板选定的 kind/format、准确 call_id/stage 以及当前片段句柄。constructor_tree.content 为对象；旧 constructor.content 才为字符串。新 evidence_links 用 claim/basis/citations，不能手写或混用行号。旧字符串/行号响应仍由独立的兼容读取器核验并留存原表示；不会自动改错行号、补引用或忽略语义违规。此修订纠正消息中遗留的字符串/行号说明，不改变器件约束或检查结果。

v0.1.7 为 DBC.quantities 的命名中间关系执行有界依赖解析：显式 quantities.名字 或无歧义短名；拒绝循环、未声明依赖、歧义输入和展开超限。有限值采用精确有理数与 memoization，求解器使用同一依赖图的派生展开式。它不赋予校准/旧帧有效性，不默认 C 整数截断、内部位宽或物理误差容限。跨单位命名代数未编码时仍为 unknown；无法求值的规范关系是上游缺口，不能把它伪报为候选数值错误。

v0.1.8 的 CheckedPhysicalLowerBound 增加可选 variables/assuming，允许对泛型频率和计数范围做有条件的算术检查。变量须有明确类型与闭区间，ticks 可为纯表达式；位宽、相位损失、频率界不能默认猜测。结果单列条件、provider_assurance=unknown、candidate_guard_conformance=not_checked。算术满足不代表来源、物理时钟、运行时守卫、上界或活性满足；组合报告仍保留这些 unknown，不能据此开启未满足的生成门禁。

v0.1.9 的生成准入独立记录必要事实、有限恢复支持、证明限制和未使用框架条目。主机/方法核对当前契约 hash、实际引用的冻结来源及行段、Constraint.evidence 的 claim 标签，以及 full 所需的专门 DBC 核对阶段；该审计通过仅表示模型辅助恢复具有可追踪支持，evidence_entailment 仍为 unknown，不要求生成前已有普遍蕴含证明。目标 FP 依赖从 DBC 连接/等待、BP 精确引用和引用闭包机械推导；输出、执行、生命周期、资源、假设及全局未决始终保守纳入。仅未使用框架条目的 unknown 可列为未使用；具体设备/FSM/数据/计时缺口、全局未决、任何 violated 和无法说明的总体状态仍阻断。无 BP 变体不使用不存在的映射缩小依赖。该修订不批准物理假设，不清除父报告 unknown，也不声称候选符合性通过。

v0.1.10 执行寄存器值和明确的数据有效性条件。寄存器 header 只引用 address 和纯常量/允许运算；WriteRegister.value 的字节由操作按 width/byte_order 追加一次，不能再放进 write_header。value 可为整数或在已提供状态环境中可解释的精确整数表达式字符串；不做隐式截断、回绕或未知变量补值。

v0.1.11 明确执行既有封闭表达式语法：PhysicalQuantity.expression 只能使用公共语义中声明的纯运算与命名关系。任意源函数调用、方法调用、反射、索引、lambda 和未声明函数不是规范公式，确定性检查将其列为违规并请求同对象修复。已支持语法中的未知变量域、位宽或数值证明仍保持 unknown；不得用原 C 补偿函数的名称代替恢复后的物理关系。

v0.1.12 给 PhysicalQuantity 增加可选 bit_width=None，修复既有位运算语法在物理关系中无法声明位宽的问题。旧调用保持默认 None，缺宽继续 unknown；每个命名关系独立有据声明，不继承消费者位宽。解释器和 Z3 使用相同的显式位操作数/结果界、不回绕左移、整数向下取整右移和限宽补码取反。显式 signed/unsigned/extract 保留输入域检查。普通有理数算术、源 C 有限精度的一致性、校准有效性和原生输出编码仍分别检查，不因增加位宽而通过。求解超时继续 unknown。

FSM 的非扩展数据掩码/常量右移守卫可以使用当前 ReadRegister/FrameLayout 已声明的同一位宽；不从数值大小猜位宽。混宽、更宽常量、左移、取反、异或、位操作中的算术提升以及无来源状态位宽保持 unknown。赋值只有直接寄存器别名保留已知位宽；算术赋值会清除旧位宽。前缀的 SSA 与实际契约解释回放使用相同约束，仍只给出有限输入见证。

数值舍入边界激励现在做带定义域、requires 和命名关系位宽的存在性求解，再用相同关系图重新计算。不能把未定义表达式的反例当成有效输入；校验字节重算后仍须满足谓词。没有满足条件的输入不等于候选通过，也不推导真实校准常数。

v0.1.13 将等待/Deadline 的事件引用与同一降低图的实际事件清单核对；明确动作 name 不自动带段名前缀，Lifecycle 的 initialize/acquire 是逻辑输入而非物理上电。缺失声明的精确锚点是引用违规，不由主机猜测重写。新的有限数据流检查从同一解释器成功提交点列出可用数据名称，指出物理关系引用了哪些不可用的帧/状态；只检查一个有限前缀，不证明全部路径、数据有效性或原生候选。

寄存器解码域和显式 FSM 状态初值/直接别名赋值可合并为保守数值范围；布尔状态保留 False/True 两种可能，不默认前提为真。算术更新、无法绑定的别名及其消费者保持未知，不能只按初值固定状态。数值证明按完整表达式/前提/命名依赖闭包选择变量，原契约和其它字段仍保留并分别检查。超出求解资源界是 unknown，不是数值违约；这些范围不证明 C 溢出、状态可达性、硬件或模型恢复的真实性。

框架选择可从公开 board Cargo 根机械读取已索引框架类型的顶层 type alias，以及通用总线/计时组件构造语句的输入依赖与相应 receiver 配置。保留原文行、hash、分支方向、cfg、宏与重名变量缺口；不把设备驱动函数体、设备组件构造或其它外设操作作为框架示例加入闭包。公共板级配置在原有文件界内优先于可选 provider 猜测；并未增加界限。语法片段不证明执行、动态派发或 provider 物理符合。

在线调用顺序按实际依赖：源 FP（变体启用时）→DBC 及必要复查→目标 FP→BP/直接生成。DBC 不依赖目标 FP；失败或显式停在 DBC 的开发作业不发起无关目标 FP 请求。显式 FP 构建作业仍独立构建两份 FP。完整路径的上游检查、材料政策和其它资源上限不变；旧消息检查点若因顺序/内容变化不再精确匹配，继续拒绝网络回退。

ReadRegister.into 未声明为持久 FSM 状态时是当前阶段的临时数据，新 acquisition 身份开始时清除；寄存器整数不能隐式替换 bool 状态。显式 acquire 逻辑事件由解释器在转移可用时建立新身份；旧回调仍不能推动新轮。全局 FSM 的并行 Assign 可用于显式保存校准状态，但这不建立未知的校准有效期、复位或配置失效保证。

前缀激励器从同一全局图为每次寄存器/帧读取生成新变量，按声明位宽/符号给出有限域，以 SSA 保存并行赋值和明确的持久状态，再用同一契约解释器复查选定路径、最小等待、Deadline 和提交。存在性求解只寻找一个输入，不是全域性质证明；回放采用零 I/O 延迟和声明的最小等待，不能据此宣称实际 provider 可实现或候选已经执行。图搜索、变量、定义、深度、时间及求解次数均有界，未编码的位操作和数据要求仍为 unknown。

数值点检查使用实际已提交的帧和提交时状态快照，后续临时帧写入不能改变预期值。显式 PhysicalQuantity.requires 在提交快照和当前使用环境中检查；命名中间关系的必要条件也传播。显式输入 domain 在提交数据点上检查；自然语言或未绑定条件继续 unknown。已编码条件明确为假而仍发布数值成功是有限观察中的违约；无法解释规范公式或缺少有效性依据是上游缺口。这里没有自动赋予旧校准数据新身份，也没有证明模型辅助恢复的条件正确。

正常路径在生成前按根因最多执行三次语义修复，每个 DBC/目标 FP/BP 至多一次；格式/补证请求另受同一共享请求/时间/费用界约束。关闭 DBC refinement 的变体不进入 DBC 修订；移除 BP 的变体不构建/修订 BP。父对象变化后使下游当前对象失效，BP 必须按新父版本重建并重算，历史不删除。FP 修复只接收框架原文、框架候选及其自身诊断，不接收混合了设备缺口的总准入报告。仍未解决的必要义务在有界尝试后关闭生成。

生成后的方法检查若返回带对象/路径的前提缺口，可由主机调度同一有界上游修复；不根据任意诊断字符串猜根因。它和生成前共享三个对象的额度，各对象至多一次。父版本变化后重新准入，再用旧源码作为种子执行 code 修复；使用当前只读父版本及最初 baseline 的累计修改，不新开 code_generate 重置额度。所有 code 的格式和补证请求仍合计最多四次；该计数不会缩减其它对象的独立格式修复界。compile_only_repair 不接收这些生成后诊断。

数值域检查可把可达的命名物理计算关系直接编码为共享算术 DAG，保留每条关系的单位检查及定义域约束；不必先把公共子表达式重复展开成大文本。定义数、节点数及递归深度仍有界，循环、名字歧义、除零、位宽缺失及不支持的算术不因此变为通过。

大型源码分析上下文可使用独立的 lossless-record-tables/v2 数据载体：按其中 decoding 规则还原 columns/rows、record_map 与 strings；它不是新的设备契约语言。完整控制/数据依赖图、配置和所有分析缺口保留。冗余语法符号索引可留在绑定摘要的原分析父材料中，当前全部原始源码仍可见，inspect_symbol(scope=source) 查询同一原始源码。该表示不推断设备语义，不删除失败路径。JSON 外层必要时仅去除缩进，逐项内容与原文不变，固定上下文上限不因此提高。

大型 DBC 专门复查可先提供全部函数/调用索引、配置和所有分析缺口；完整控制/数据图仍保存在 hash 固定的父材料，所有原始源码/手册继续直接可见。需要某个源效果的完整函数/被调用闭包时，outcome=needs_evidence，context_requests 中 scope=internal_tools，query 为 JSON 字符串，例如 `{"tool":"slice_device_effects","arguments":{"roots":["实际函数名"]}}`，并填写具体 question/reason。仅可调用 tool_interfaces 实际列出的工具，参数按其有限 schema；同样支持 inspect_symbol、query_framework、resolve_configuration、retrieve_device_evidence、check_contract。主机执行并把原文片段或带来源的机械分析/诊断加入下一次同对象调用；不执行任意命令或文件路径。未知工具、错误参数、未解析函数根或超限闭包明确拒绝，不推测效果，也不把机械分析当设备语义证明。

正常 SD adapter 的主机自动循环会在准备的 host 副本中应用累计候选、公开编译并执行方法拥有的原生检查。它通过固定、材料 hash 绑定的主机接口调用，不把任意 shell/路径工具交给模型。最多五份候选，累计四次 code 修复；格式修复也消耗这四次。compile_only_repair 不接收候选内部检查结果或反例。最后一份实际应用的源码在主机冻结后，才可独立评分；编译/有限内部检查不代表独立评分或硬件通过。

`dbc_review=true` 也是可信主机请求字段，仅用于 DBC 专门核对及其有界格式修复；模型不能设置它，关闭 refinement 的变体拒绝它。它记录核对阶段确已执行，不证明证据蕴含为真。首次恢复或普通格式修复不自动获得该标记，导入时不能冒充已完成核对。

默认生产调用使用 `contract_transport=constructor_tree`。这只是现有语言的 JSON 树传输：artifact.format 为 constructor_tree，content 为对象。构造器写 `{"$constructor":"名字","参数名":值}`，变长参数按目录名称填数组（如 Sequence.steps）；普通字典/数组保留，必要时用 `{"$tuple":[]}` 和 `{"$map":[[key,value]]}` 表示元组及非字符串键。精确十进制写 `{"$decimal":"0.01"}`，整数直接写 JSON 整数，不经 binary64。主机无损渲染为同一构造式，再执行原目录、引用、类型和语义检查；语义集合没有增加。原树与派生表达式 hash 留证。v0.1.2 的 args/fields 包装和旧 constructor 字符串仍可读；后者的有界语法规范化政策保持。

每个实际提供的 context 片段带内容/行段固定的 citation_id。模型的 evidence_links 可写 claim、basis、citations（这些实际句柄的列表）。主机仅还原为各片段自己的 material_id 与行号，不合并跨过未提供的行；同一断言与依据逐项保留，原句柄/原文摘要/行段留证。这不证明原文支持断言。旧显式行号仍严格检查，不能引用片段之外的行。

- 构造器正文是受限数据表达式。数值参数写整数、有限十进制常量，或字段明确接受的有理数字符串（如 `"1/3"`）；不能执行 Fraction 等 Python 函数。计算关系和守卫写在字符串中。
- 时间界写 `"1 ms"`、`"10 us"`、`"0.5 s"` 等带单位字符串。tick 与物理时间不同维；不能用裸数字代替时间。物理事件和操作身份分别保留，提交、物理结束和回调不等同。
- 当前单位解释器接受 `s, ms, us, µs, ns, tick, Hz, V, Pa, hPa, °C, degC, %RH, percent_RH, lx, lux, ppm, ppb, 1`。ppm/ppb 分别是浓度的 10^-6/10^-9 比例，不能冒充原始计数；lx/lux 为照度。未支持的单位保持 unknown，不能凭名称换单位或改物理意义。OutputEncoding.unit 应使用基础物理单位，scale/offset 明确表示 `physical = stored * scale + offset`；不要在 unit 和 scale 中重复比例。SensorInterface.unit 可忠实记录原生接口描述，但必须与 encoding 另行核对。
- 整数 OutputEncoding.storage_type 使用 `i8/i16/i32/i64/i128` 或相应 `u` 类型；range 是合法存储区间二元组。复合结构或平台 usize 的实际位宽未建立时保留缺口。Rounding 必须说明取整模式，超域默认 report_gap。
- 已知单位、比例和存储类型应分别保留；例如未定宽 `usize` 可忠实记录为 storage_type，位宽/range 未恢复时用 Unspecified。这样的部分 OutputEncoding 不具有整数溢出/范围通过结论，仍可供后续恢复已知字段。不能把已知子字段全部替换成一个宽泛 Unspecified。
- 已建立 IEEE 二进制格式时，浮点 storage_type 使用 `f32` 或 `f64`。从规范有理数直接按 Rounding 量化，保留精确误差、位模式和有限值；不经过另一浮点宽度再舍入。支持次正规数及有符号零；无穷/NaN 不作为成功样本。合法 range 和物理 error_bound 仍须给出依据；未知精度要求不能因格式正确而通过。
- CRCProtectedWords.encoding 是 `{ "width": 整数字宽, "signed": 布尔值, "byte_order": "big"或"little" }`。字宽须为整字节。其它排列直接使用 FrameLayout、Field、Checksum。字段 offset/width 单位为 bit，checksum 区间为半开字节区间；不能部分校验后发布整帧。
- FSM.variables 当前可执行声明为 `{变量: {"type": "bool"或"int"或"real", "initial": 初值}}`。外部事件、未声明符号、未解析条件和进展前提不能默认为成立。Assign 并行读取同一旧快照，类型必须一致。
- CheckedPhysicalLowerBound.clock_bounds 的显式形式为 `{ "frequency_max": Hz数值, "minimum_ticks": 最小tick数, "maximum_ticks": 最大安全tick数, "reference_not_before_anchor": 布尔值, "callback_not_before_deadline": 布尔值 }`；另给 ticks、phase_loss、reference_event。布尔值和数字仍须有 provider/原文依据；写成 True 不等于证据已经建立。引用形式缺少可解析参数时保持 unknown。
- Ref 只解析当前实际提供且完整、身份固定的材料或已声明父别名。已知父引用存在是确定性检查；不能据此宣称原文支持全部断言。
- BindAsyncCall.call 引用父 FP 的调用，completion 用 FromFP 指向父 FP 中的 Callback 字段。EventRef 表示运行时事件，放在 EventBinding 等事件关系中，不能替代 completion 的父对象路径；其中 instance 使用 current，操作名称放 operation。导入的 BP 仍须重算组合检查，不能因父版本相同而跳过确定性违规。
- FromDBCFrameLayout 仅表示接收帧布局的长度。SPI 全双工调用的总长度还包括命令/头部及相应读时钟，应从完整 DBC 操作导出（FromDBCOperation）；不能把帧长直接当作完整 SPI 长度。BP 修订后，旧代码检查失效；只有核验新 BP 请求凭据、确认 DBC/目标 FP 未变，并对相同候选执行新原生检查后，才可在不重置累计次数的前提下把代码种子绑定到新 BP。

已执行的检查包括受限解析、部分类型/单位/布局/数值解释、事件等待与 tick 下界、全局 FSM 降低/有限解释、有限请求与 buffer 观察、显式编码的 Z3 算术及部分绑定义务。报告逐项区分 satisfied、violated、unknown。语义目录中未编码的性质、证据蕴含、未恢复的 provider 保证和活性不因语法正确而通过。当前没有候选原生执行结果时，不得把合成轨迹或静态检查当作原生候选执行。

纯数值解释和 Z3 支持绝对值不超过 64 的字面整数幂。负幂另检查底数非零；分数或变量指数保持 unknown。生成准入检查按阶段调度：BP 中关于未来候选 implementation_conformance 的 unknown 留待生成后执行，不循环要求生成前已经执行候选。其它未解决的必要上游检查仍关闭生成；准入通过不修改父报告，也不等于候选符合性通过。

传输解析允许两种有审计的机械规范化：删除 JSON 字符串外尾逗号；在已有外层闭合符之前补齐已知构造器调用的右圆括号，最多八个。后者不补 EOF、元组/列表/字典闭合符，不更改名称、字段或字面值；规范化后仍执行完整目录/参数解析。原始响应与修改位置、原始及派生摘要均保留。规范化不证明语义正确，也不消除 unknown。
